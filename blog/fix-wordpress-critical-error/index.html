How to fix "There has been a critical error" in WordPress

You open your website and instead of your homepage you see one line: "There has been a critical error on this website." No menu, no content, nothing. It's scary, but it's one of the most common WordPress problems, and it's almost always fixable without losing anything.

Here's what's going on, and how to fix it yourself, step by step.

What the error actually means

WordPress runs on a programming language called PHP. When a piece of PHP code crashes badly enough that the page can't finish loading, WordPress stops and shows this message instead of a half-broken page.

In practice, nine times out of ten the crash comes from one of these:

  • A plugin update that clashes with another plugin or your theme
  • A theme update, or a change to your theme's files
  • Your host upgrading PHP to a newer version your old plugins don't support
  • Running out of memory on cheap hosting

The good news: your content (pages, posts, products, orders) is stored separately in the database. The error stops it being shown, but it doesn't delete it.

Step 1: Check your email for the recovery link

Since version 5.2, WordPress emails the site's admin address when this happens. Look for an email with a subject like "Your Site is Experiencing a Technical Issue" (check spam too).

It tells you which plugin or theme caused the crash, and gives you a special recovery mode link. Click it, log in, and WordPress lets you into the dashboard with the faulty plugin paused. Then you can:

  1. Go to Plugins and deactivate the plugin it named
  2. Check your site loads again
  3. Look for an update to that plugin, or find an alternative

If you got the email, that's often the whole fix.

Step 2: No email? Turn the plugins off by hand

If the email never arrived, you can switch off every plugin at once without logging in:

  1. Log in to your hosting control panel (cPanel, Plesk or your host's own dashboard) and open the File Manager
  2. Go to wp-content
  3. Rename the folder plugins to plugins-off
  4. Reload your site

If the site comes back, a plugin was the culprit. Rename the folder back to plugins, then go to Plugins in your dashboard. They'll all be deactivated. Turn them on one at a time, reloading the site each time. When the error comes back, you've found the one causing it.

Step 3: Rule out the theme

If turning off plugins didn't help, try the theme. In File Manager, go to wp-content/themes and rename your active theme's folder (for example astra to astra-off). WordPress will fall back to a default theme such as Twenty Twenty-Four, if one is installed.

If the site loads, the problem is in your theme, often a recent update or an edit to functions.php.

Step 4: Check your PHP version

Hosts regularly move sites to newer PHP versions. Older plugins and themes sometimes can't cope. In your hosting panel, look for "PHP version" or "Select PHP version". If it changed recently, try moving back one version (for example from 8.3 to 8.2) as a short-term fix, then update the plugin that's struggling.

Step 5: Turn on the debug log

If you're still stuck, WordPress can write the exact error to a file. In File Manager, open wp-config.php and, just above the line that says "That's all, stop editing!", add:

define( 'WP_DEBUG', true );
define( 'WP_DEBUG_LOG', true );
define( 'WP_DEBUG_DISPLAY', false );

Reload the site, then open wp-content/debug.log. The last lines name the file that crashed, and the folder name tells you which plugin or theme it belongs to. Remove those lines again once you're done.

How to stop it happening again

  • Back up before updating. A free plugin like UpdraftPlus can do it automatically.
  • Don't update everything at once. Update plugins one by one so you know which one broke something.
  • Delete plugins you don't use. Fewer plugins means fewer clashes.
  • Keep WordPress, your theme and plugins up to date, but not on the day before a big launch.

Short version: check your email for the recovery link; if there isn't one, rename the plugins folder, then the theme folder, and check your PHP version. One of those fixes most critical errors.
